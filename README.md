# Bank Request Decoder

Веб-приложение, которое объясняет запросы банка (due diligence, KYC, источник средств, UBO, санкции) простым языком и пишет черновик ответа. В нём есть тест-лаборатория: она прогоняет одни и те же кейсы через разные ИИ-модели и сравнивает качество, скорость и стоимость.

## Что внутри

| Страница | Что делает |
|---|---|
| **Разбор запроса** (`/`) | Продукт для клиента: вставил запрос банка → объяснение, список документов, вопросы, черновик ответа. Интерфейс на RU / EN / LV. |
| **Тест-лаборатория** (`/lab`) | Выбираешь кейсы и модели → запуск → таблица по каждой модели: валидный ответ, пойманные ловушки, время, токены, стоимость, ваша оценка 1–5. |
| **Настройки** (`/settings`) | API-ключи (Anthropic, OpenAI, xAI/Grok, Google Gemini, OpenRouter), список моделей и цены. |

Модель «Демо-заглушка» работает без ключа: можно проверить весь интерфейс, ничего не покупая.

## Запуск на своём компьютере

1. Установи **Node.js 22 LTS**: https://nodejs.org (кнопка LTS).
2. Открой терминал в папке проекта и выполни:
   ```
   npm install
   npm run dev
   ```
3. Открой в браузере http://localhost:3000

Остановить сервер: `Ctrl + C` в терминале.

## API-ключи

- Ключи вводятся на странице **Настройки** и сохраняются в `data/settings.local.json`.
- Этот файл в `.gitignore`: в GitHub он **не попадает**. Каждый вводит свои ключи у себя.
- Самый простой вариант — один ключ **OpenRouter** (https://openrouter.ai/keys): через него доступны Claude, GPT, Grok, Gemini, DeepSeek и другие модели, а стоимость считается автоматически.
- У каждого провайдера поставь **лимит расходов** в его кабинете.
- Приложение рассчитано на работу **локально**. Не выкладывай его в интернет в таком виде: страница настроек ничем не защищена.

## Работа вдвоём через GitHub

Один раз (тот, кто создаёт репозиторий):
```
git init
git add .
git commit -m "Первая версия"
```
Создай **приватный** репозиторий на github.com (без README), затем:
```
git remote add origin https://github.com/<логин>/bank-request-decoder.git
git branch -M main
git push -u origin main
```
На GitHub: Settings → Collaborators → добавь второго человека.

Второй человек один раз:
```
git clone https://github.com/<логин>/bank-request-decoder.git
cd bank-request-decoder
npm install
npm run dev
```

Каждый день:
```
git pull                      # забрать изменения партнёра
# ...работа...
git add .
git commit -m "что сделал"
git push                      # отправить свои
```

## Где что лежит

```

app/lab/page.tsx          тест-лаборатория
app/settings/page.tsx     настройки и ключи
app/api/*                 серверная часть (вызов моделей, кейсы, прогоны)
lib/prompt.ts             ИНСТРУКЦИЯ ДЛЯ МОДЕЛИ — главный файл для улучшения качества
lib/providers.ts          как вызывать каждого провайдера
data/cases/*.json         тестовые кейсы (добавь файл — кейсы появятся в лаборатории)
data/runs/*.json          результаты прогонов (попадают в Git, чтобы видеть их вдвоём)
data/settings.local.json  ваши ключи (НЕ в Git)
```

## Формат тестового кейса

```json
{
  "id": "S01",
  "src": "syn",
  "title": "Короткое название",
  "client_type": "individual",
  "bank_request_text": "Текст запроса банка",
  "user_context": "Что клиент говорит о себе (можно пусто)",
  "trap": "Что этот кейс проверяет",
  "expect_safety": false
}
```
`expect_safety: true` означает, что модель обязана предупредить (обман, обход санкций). `expect_scam_warning: true` — что модель должна распознать фишинг.
