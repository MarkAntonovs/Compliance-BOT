# Bank Request Decoder

Веб-приложение, которое объясняет запросы банка (due diligence, KYC, источник средств, UBO, санкции) простым языком и пишет черновик ответа. Работает на Claude. В нём есть «Проверка качества»: прогон тестовых кейсов и оценка каждого разбора по критериям.

## Что внутри

| Страница | Что делает |
|---|---|
| **Разбор** (`/`) | Продукт для клиента: описывает ситуацию или вставляет запрос банка → риски (бенефициары, источник средств, санкции ЕС), документы и где их взять, что сделать, черновик ответа банку. RU / EN / LV. Ничего не сохраняет. |
| **Конвейер** (`/pipeline`) | Генератор придумывает реалистичные вымышленные кейсы по теме, бот сразу их разбирает. |
| **Проверка** (`/review`) | Андрей читает кейс и разбор: «Верно» или «Есть ошибки» + что не так и как правильно. Кнопка «Сделать правилом» и «Прогнать заново». |
| **Правила** (`/rules`) | Правила эксперта. Бот получает все работающие правила с каждым запросом. |
| **Настройки** (`/settings`) | Ключи и модель. |

Как это учится: поправка Андрея → Claude формулирует правило → Андрей утверждает → правило сразу работает в боте. Модель не дообучается — знания лежат в правилах (база данных) и в инструкции (`lib/agents.ts`).

Модель: если в `data/models.json` нет настоящей модели, а ключ Anthropic есть, автоматически берётся новейший Claude Sonnet. Другую модель можно задать переменной `ANTHROPIC_MODEL` в Vercel.

База данных: Postgres (Neon), переменная `DATABASE_URL`. Таблицы создаются сами при первом запросе, первые 3 правила Андрея добавляются автоматически.

## Запуск на своём компьютере

1. Установи **Node.js 22 LTS**: https://nodejs.org (кнопка LTS).
2. Открой терминал в папке проекта и выполни:
   ```
   npm install
   npm run dev
   ```
3. Открой в браузере http://localhost:3000

Остановить сервер: `Ctrl + C` в терминале.

## API-ключи и модели

- **На своём компьютере:** ключи вводятся на странице **Настройки** и сохраняются в `data/settings.local.json`. Этот файл в `.gitignore`, в GitHub он **не попадает**.
- **Список моделей** хранится в `data/models.json`. Он попадает в GitHub: добавили модель локально → закоммитили → сайт на Vercel использует те же модели.
- Самый простой вариант для тестов — один ключ **OpenRouter** (https://openrouter.ai/keys). Для одной модели (например, только Claude) — ключ напрямую у провайдера.
- У каждого провайдера поставь **лимит расходов** в его кабинете.

## Сайт на Vercel

На сервере файлы сохранять нельзя, поэтому всё задаётся в **Vercel → Project → Settings → Environment Variables**:

| Переменная | Зачем |
|---|---|
| `SITE_PASSWORD` | Пароль на весь сайт. Пока продукт не проверен — обязательно |
| `ADMIN_PASSWORD` | Пароль на «Проверку качества» и «Настройки». Без него эти разделы на сервере закрыты |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `XAI_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY` | Ключи нужных провайдеров |
| `MAX_REQUESTS_PER_HOUR` | Сколько разборов в час можно с одного IP (по умолчанию 30) |

После изменения переменных нажми **Redeploy**. Браузер спросит логин и пароль: логин любой, пароль — из переменной.

«Проверку качества» можно запускать и на Vercel: прогон сохранится в браузере, а кнопка «Скачать прогон» даст файл, который можно положить в `data/runs/` и закоммитить. Локально прогоны сохраняются в `data/runs/` сами.

## Работа вдвоём через GitHub

Один раз (тот, кто создаёт репозиторий):
```
git init
git add .
git commit -m "Первая версия"
```
Создай **приватный** репозиторий на github.com (без README), затем:
```
git remote add origin https://github.com/<логин>/bank-request-decoder.git
git branch -M main
git push -u origin main
```
На GitHub: Settings → Collaborators → добавь второго человека.

Второй человек один раз:
```
git clone https://github.com/<логин>/bank-request-decoder.git
cd bank-request-decoder
npm install
npm run dev
```

Каждый день:
```
git pull                      # забрать изменения партнёра
# ...работа...
git add .
git commit -m "что сделал"
git push                      # отправить свои
```

## Где что лежит

```
app/page.tsx              страница «Разбор запроса»
app/quality/page.tsx      проверка качества
data/rubric.json          критерии оценки разбора
app/settings/page.tsx     настройки и ключи
app/api/*                 серверная часть (вызов моделей, кейсы, прогоны)
lib/prompt.ts             ИНСТРУКЦИЯ ДЛЯ МОДЕЛИ — главный файл для улучшения качества
lib/providers.ts          как вызывать каждого провайдера
data/cases/*.json         тестовые кейсы (добавь файл — кейсы появятся в «Проверке качества»)

data/models.json          список моделей (в Git)
proxy.ts                  пароли на сайт и админку (на сервере)
```

## Формат тестового кейса

```json
{
  "id": "S01",
  "src": "syn",
  "title": "Короткое название",
  "client_type": "individual",
  "bank_request_text": "Текст запроса банка",
  "user_context": "Что клиент говорит о себе (можно пусто)",
  "trap": "Что этот кейс проверяет",
  "expect_safety": false
}
```
`expect_safety: true` означает, что модель обязана предупредить (обман, обход санкций). `expect_scam_warning: true` — что модель должна распознать фишинг.
